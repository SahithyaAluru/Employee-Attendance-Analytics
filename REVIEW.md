# REVIEW.md

Defects found in the starter `app/main.py` (line numbers = the original starter). All are fixed in
the current `app/main.py`; the "How you'd notice it" column describes the check we actually ran
against the local app + seeded sample data.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (L33-37) | Floors minutes **before** comparing against the 10-min grace: `int(delta/60) > 10` is false for 10.02 min, so a punch at 09:40:01 returns 0 (contract says 10). Also rebuilds shift-start with `punch_in.replace(...)` on a naive, server-local clock: wrong time zone, wrong calendar day for overnight shifts, no second-truncation. | Punch-in 09:40:01 IST on EMP0001 -> expected `late_minutes: 10`, starter gives `0`. | Compute `delta_seconds` on aware UTC datetimes from the record's IST attendance date (R1); grace test `delta <= 600 -> 0`, else `delta // 60`. Tests "R2 09:40:00 -> 0 / 09:40:01 -> 10 / 10:15:59 -> 45". |
| 2 | `compute_work_hours` (L40-41) | Python `round()` uses banker's rounding (half-to-even); R4 requires **half-up** to 2 decimals, so 8.025 h differs (8.02 vs 8.03). | Punch times exactly 28890 s apart (8.025 h): starter returns 8.02, contract wants 8.03. | `Decimal(sec)/Decimal(3600).quantize(0.01, ROUND_HALF_UP)`. Test "R4 half-up 8.025 -> 8.03". |
| 3 | `compute_overtime` (L44-47) | Missing R3's 30-minute threshold: 5 min after shift end returns 5, contract says **0**. Also builds shift-end with `.replace(hour=..)` on `date_str` - for overnight shifts the end lands on the *same* day, e.g. sample #7's 06:40 punch-out yields ~1420 min instead of 40. | Sample doc 1 (out 18:35, shift ends 18:30): starter computes 5, sample data says `overtime_minutes: 0`. Overnight sample #7 breaks the same helper. | `shift_end_dt()` adds a day when overnight; `delta < 1800 -> 0` else `delta // 60`. Tests "R3 5min -> 0", "R3 40min -> 40". |
| 4 | `punch_in` (L102-103) | `datetime.fromtimestamp(...)` / `datetime.now()` use the **server's** local zone, and `date = ts.date()` is the server calendar date, not IST (R1). On a UTC host evening/overnight punches land on the wrong date; sub-second precision never truncated (R1). | Punch 01:00 IST for the 22:00-06:00 shift: starter files it on the punch's own day; contract says the **previous** day. | `ms_to_dt()` -> aware UTC truncated to whole seconds; `attendance_date()` converts to IST + overnight rule. Tests "overnight punch -> date 07-20", "second truncation". |
| 5 | `punch_in` (L113) | No check the employee exists: `emp["shift_start"]` on `None` raises `TypeError` -> **500** (contract: 404). | `POST /attendance/punch-in {"emp_code":"EMP4044"}` -> 500 instead of 404. | Explicit `if emp is None: raise HTTPException(404)`. Test "punch-in unknown emp -> 404". |
| 6 | `punch_in` (L104-118) + `create_employee` (L79) | Check-then-insert race: two identical simultaneous punch-ins both pass `find_one` and both insert -> two 201s (contract: exactly one 201, rest 409). No unique index existed to back-stop it. | Fire 4 identical punch-ins in parallel -> starter can return four 201s / duplicate rows. | Unique indexes `(emp_code, date)` and `emp_code` at startup; insert raises `DuplicateKeyError` -> 409. Tests "concurrent punch-ins -> one 201" (4 threads: 201,409,409,409) and "concurrent create -> one 201". |
| 7 | `punch_in` (L107) | `status` accepted verbatim: clients can create `ABSENT`/`LEAVE`/garbage - contract says punch-in only allows PRESENT/WFH/ON_DUTY (422 otherwise). | `POST ... {"status":"ABSENT"}` -> starter stores it. | Pydantic `Literal["PRESENT","WFH","ON_DUTY"]`. Test "status ABSENT -> 422". |
| 8 | `PunchInIn.punched_at` (L64-66) | No epoch-ms validation: floats (`1.75e12`), numeric strings, seconds-scale values (`1751767800`) are silently coerced - contract requires 422 for all. | Requests with float / string / seconds values: starter accepts all; each must be 422. | `epoch_ms_field` "before" validator: rejects non-int (incl. bool) and values outside `[1e11, 4102444800000]`. Tests "float/string/seconds -> 422". |


| 9 | `punch_in` response (L119-120) | Leaks `id` = stringified `_id` - contract: "_id never appears in a response; attendance records have no id either". Also returns raw BSON datetimes (ISO strings) instead of epoch-ms integers. | `POST /attendance/punch-in` response contains `"id": "..."` and `"punch_in": "2026-07-..."`. | `record_out()` strips `_id`/`id` and converts `punch_in`/`punch_out`/`history` dates to epoch ms. Tests "no id/_id leaked", "punch_in epoch ms int". |
| 10 | `list_employees` (L92) | `skip = page * page_size` - off-by-one: page 1 skips a full page, so with 6 employees `GET /employees` (page 1) returns `items: []`. | `GET /employees?department=Engineering&page=1` -> `items: []` while `page=0` returns both rows (the report that kicked off this review). | `skip = (page - 1) * page_size`; `page` validated `ge=1` so page 0 -> 422. Test "dept filter page1 items". |
| 11 | `list_employees` (L94) | `total = count_documents({})` ignores the `department` filter - contract R10: total reflects applied filters. Reported response showed `total: 6` for a 2-row Engineering page. | `GET /employees?department=Engineering` -> `total: 6` instead of 2. | `count_documents(query)` with the same filter. Test "dept filter total=2". |
| 12 | `list_employees` (L89-96) | No sort (contract: `emp_code` ascending), no `page`/`page_size` bounds (`page_size=1000` accepted; contract max 100, `page >= 1` else 422). | `page_size=1000` -> 200; `page=0` accepted. | `.sort("emp_code", ASCENDING)` + `Query(ge=1)` / `Query(ge=1, le=100)`. Tests "page=0 -> 422", "page_size=101 -> 422". |
| 13 | `create_employee` (L80-82) | `datetime.now()` naive local time for `created_at` (server-tz-dependent instant) returned as ISO string, not epoch ms. No input validation: bad email/emp_code/`shift_start == shift_end` all accepted (contract: 422). | `POST /employees` with `email: "bad"` -> 201; `shift_start == shift_end` -> 201; `created_at` is a string. | `datetime.now(UTC)` truncated to seconds; `employee_out()` -> epoch ms; `Field(pattern=...)`, date validator, shift-difference validator. Tests "bad email -> 422", "shift==shift -> 422", "short emp_code -> 422", "created_at epoch ms int". |
| 14 | `list_attendance` (L144-147) | Loads **every** matching document into Python (`list(find(q))`), sorts and slices in memory - O(n) per request; on the ~100k-record grader dataset this is the fast-path killer the problem statement warns about (`total` also computed as `len(docs)`). | Time `GET /attendance?page_size=20` on 100k docs: full collection transfer per request. | DB-side `count_documents`, `.sort()`, `.skip()`, `.limit()` - only one page crosses the wire. |
| 15 | `list_attendance` (L145, L148-150) | Sort is only `date` desc - missing contract's `emp_code` ascending tiebreak. Response leaks `id` and returns ISO strings. `date_from > date_to` accepted (must be 422); unvalidated `status` enum (must be 422). | `?date_from=2026-07-10&date_to=2026-07-01` -> 200 empty (must be 422); `status=BOGUS` -> 200 (must be 422); same-date rows in unstable order. | `.sort([("date", -1), ("emp_code", 1)])`; dates typed `date` + explicit range check; `status` typed `Literal[...]`; `record_out()`. Tests "sort date desc, emp_code asc", "date_from>date_to -> 422", "bad status -> 422". |
| 16 | `health` (L72-74) | Never touches MongoDB - returns 200 even when the database is unreachable; contract requires 503 on ping failure. | Cut DB connectivity (the Atlas allowlist issue we hit) -> starter still says `{"status":"ok"}`. | `client.admin.command("ping")` in try/except -> 503; `serverSelectionTimeoutMS=5000` so it fails fast. |
| 17 | Module level (whole file) | **No indexes ever created** - contract: "Create all indexes at startup, idempotently." Without them there is no uniqueness guarantee (see #6) and list/analytics queries COLLSCAN on 100k docs. | `db.employees.getIndexes()` after startup -> only `_id`. | `ensure_indexes()` in FastAPI lifespan: unique `emp_code`, unique `(emp_code, date)`, `(department, emp_code)`, `(date, emp_code)`; rerunning is a no-op. |

## Additional findings in the working implementation

| Where | Defect | Verification and fix |
|---|---|---|
| `regularize` | A supplied integer epoch value was passed to `dt_to_ms`, which expects a datetime, causing a 500. | Convert input with `ms_to_dt` before calculations and storage. Integration checks verify the response, BSON datetime storage, truncation and nested history values. |
| `regularize` legacy defaults | Missing derived fields were compared to `None`, so a no-op could create a false history entry. | Compare missing half-day to false and missing late/overtime to zero. |
| `regularize` / `punch_out` concurrent updates | Comparing only status and punch times could use stale derived values or audit state. | The atomic update compares all mutable fields and history length; concurrent requests either succeed with retained history or return 409. |
| Input models | Explicit null status could be treated as omitted. | Reject null status and unsupported fields; ignore the four derived input fields as the contract explicitly requires. |
| Startup | Index failures were swallowed while the server continued accepting writes without uniqueness guarantees. | Index creation must succeed before startup completes. |
| `record_out` | Missing late/overtime or null punch fields were omitted from responses. | Supply contract defaults for legacy records. |
| Business validation | Explicit 422 errors returned a string instead of the contract's validation error array. | Raise `RequestValidationError`; HTTP checks verify detail arrays. |
| Calendar validation | Pydantic's date conversion accepted epoch-second strings and datetime strings for calendar dates. | Apply a shared strict YYYY-MM-DD validator to calendar query and path parameters. |
| Analytics and explain | Five contract endpoints were absent. | Implement shared MongoDB pipeline builders for summaries, ranking, calendar gaps and moving averages, plus executionStats explain using identical filters and hints. |

The repeatable integration checks are in `tests/check_api.py`; `--scale` exercises
100,000 additional records in an isolated database.

## Existing choices retained

* **`load_dotenv()` at import** - looks like the classic "dotenv overrides real env" bug, but python-dotenv never overrides variables that already exist, so real environment variables do win (contract satisfied). Kept.
* **`IST = timezone(timedelta(hours=5, minutes=30))`** - correct: India has no DST, a fixed offset is right.
* **Sync PyMongo instead of Motor** - fine: FastAPI runs `def` endpoints in a threadpool; async adds complexity with no benefit at this scale, and the contract explicitly allows "PyMongo or Motor".
* **Returning the whole inserted document from POST** - convenient and allowed; the problems were only *which fields* were in it (`id`, wrong types), fixed in #9/#13.
* **Error message text** (e.g. `"emp_code already exists"`) - the contract fixes status codes and response field names, not message wording; kept as-is.
